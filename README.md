# Webcam Eye Tracker

Web カメラだけで視線（画面上のどこを見ているか）を推定する、**ブラウザ完結**のアイトラッカーです。
インストール不要・サーバ不要で、映像も推定結果も端末の外に出ません。

```
カメラ映像 → MediaPipe FaceLandmarker (478点/虹彩込み)
          → 特徴量 (虹彩オフセット + 頭部姿勢)
          → リッジ回帰 (9点キャリブレーションで学習)
          → 1€ フィルタ
          → 画面座標
```

## できること

- 視線ドットのリアルタイム表示
- 9 点キャリブレーション（点をクリックして注視するだけ）
- **精度チェック** — キャリブレーションに使っていない 5 点で誤差を px と概算角度で表示
- 注視ヒートマップ
- まばたき検出（閉眼中は推定を止める）
- 視線ログの CSV 書き出し
- キャリブレーション結果の localStorage 保存（次回は読み込むだけ）

## 使い方

カメラ API は secure context 限定なので、`file://` では動きません。ローカルサーバ経由で開いてください。

```bash
git clone <このリポジトリ>
cd webcam-eye-tracker
npm start          # python3 -m http.server 8080
# → http://localhost:8080 を開く
```

1. **カメラを開始** — 初回は MediaPipe のモデル（約 3 MB）を CDN から取得します
2. **キャリブレーション (9点)** — 表示された点を**見つめたままクリック**。9 回繰り返します
3. **精度を測る** — 別の 5 点で実誤差を確認。ずれていれば 2 に戻る

途中で中止したいときは `Esc`。

### 精度の目安

デスクトップの内蔵カメラで、顔を動かさなければ **画面上 1〜3°（60 cm 視距離で 100〜200 px 程度）** というのが Web カメラ方式の相場です。
これは「この段落を見ている」は分かるが「この単語を見ている」は分からない精度で、赤外線を使う専用機（0.5° 前後）とは別物と考えてください。

精度を上げるコツ：

- 顔に正面から光を当てる（逆光が一番効きます）
- キャリブレーション時と同じ姿勢・同じ距離を保つ
- メガネの反射を避ける
- 姿勢が変わったら再キャリブレーションする

## 仕組み

### 特徴量 (`js/features.js`)

虹彩中心が目頭・目尻の中点からどれだけズレているかを、目の横幅で正規化した値が主信号です。
これだけだと頭が動いた瞬間に破綻するので、ランドマークから直接計算できる頭部姿勢の代理変数を足しています。

| 特徴 | 中身 |
|---|---|
| 虹彩オフセット | 左右それぞれの `(nx, ny)` と、その平均・2 次項 |
| ヨー | 鼻先から左右の目尻までの距離の差 |
| ピッチ | 目の線に対する鼻先の縦位置 |
| ロール | 左右の目尻を結ぶ線の角度 |
| スケール | 両目尻間距離（カメラからの距離の逆数に相当） |
| 位置 | 両目の中点の画面内座標 |
| 交差項 | 虹彩オフセット × 頭部姿勢 |

計 24 次元。頭を動かすと虹彩オフセットと頭部姿勢が相関するので、その交絡を回帰に解かせる、という設計です。

### 回帰 (`js/math.js`, `js/gaze.js`)

特徴量を z 標準化し、切片を除いて L2 正則化したリッジ回帰で `(x, y)` を直接予測します。
9 点 × 約 25 サンプル = 225 行に対して 25 パラメータなので、正則化込みなら安定して解けます。
解法は Gauss-Jordan（部分ピボット選択つき）で、外部ライブラリはありません。

### 平滑化 (`js/filter.js`)

1€ フィルタ。静止時は強く平滑化し、サッカード時は遅延を出さない、という視線に向いた特性です。
スライダーでカットオフ周波数を調整できます。


## テスト

```bash
npm test
```

線形代数とフィルタの単体テストに加えて、`test/pipeline.test.js` では
「虹彩位置が視線と頭部姿勢の既知の関数になっている合成顔」を作り、
9 点キャリブレーション → 未知の 5 点で予測、という一連の流れが
数値的に成立することを確認しています。

## 動作環境

Chrome / Edge / Safari の比較的新しいバージョン。WebGL (MediaPipe の GPU デリゲート) と
`getUserMedia` が必要です。iOS Safari でも動きますが、画面が小さいぶん角度誤差は大きくなります。

## 既知の限界

- 頭部が大きく動くと精度が落ちます。多点・多姿勢でキャリブレーションすると多少改善します
- キャリブレーションはウィンドウサイズに紐づきます。リサイズしたら測り直してください
- 眼鏡の強い反射やコントラストの低い照明では虹彩ランドマークが不安定になります
- 画面外への視線はクランプされます（画面内という前提のモデルです）
