# Webcam Eye Tracker

Web カメラだけで視線（画面上のどこを見ているか）を推定する、**ブラウザ完結**のアイトラッカー。
インストール不要・サーバ不要・映像も推定結果も端末の外に出ません。

```
カメラ映像 → MediaPipe FaceLandmarker (478点 / 虹彩込み)
          → 特徴量 24次元 (虹彩オフセット + 頭部姿勢 + 交差項)
          → リッジ回帰 (交差検証でλ選択 + ロバスト再重み付け)
          → 1€ フィルタ → I-VT 注視点検出
          → 画面座標 / 注視イベント
```

---

## 「Webカメラだけで実用レベル」は可能か

**用途によります。** ここを誤魔化すと導入してから破綻するので、先に線を引いておきます。

キャリブレーション済み・顔を大きく動かさない条件で、現実的に出る精度は
**画面上 1〜3°**（視距離 60 cm なら **40〜120 CSS px** 相当）です。
`npm start` → 「精度を測る」で、あなたの機材での実測値が出ます。

| 用途 | 可否 | 必要精度の目安 |
|---|---|---|
| 要素単位の注目度（どのカード / 段落 / 画像を見たか） | ✅ 実用的 | 2〜3° |
| UI 評価用のヒートマップ・走査経路 | ✅ 実用的 | 2〜3° |
| 大きめのターゲットへの視線入力（dwell クリック） | ✅ 実用的 | 2° / 3cm 以上のボタン |
| 広告・サムネイルの注視分析 | ✅ 実用的 | 2〜3° |
| 行単位の読書追跡 | ⚠️ 条件付き | 1〜1.5°、行間に余裕が要る |
| 単語・文字単位の読書追跡 | ❌ 無理 | 0.5° 以下 |
| マイクロサッカード、瞳孔径、臨床・研究用途 | ❌ 無理 | 専用機の領域 |

赤外線を使う専用機（Tobii 等）は 0.3〜0.5° で、しかも頭が動いても落ちません。
Web カメラ方式は**別のカテゴリの道具**だと考えてください。
「どこを見ているか」ではなく「**何に注目していたか**」を測る道具です。

### 精度を実用側に寄せるために効くこと（効果の大きい順）

1. **顔に正面から光を当てる。** 逆光が一番効きます。虹彩ランドマークが崩れると何をしても無駄です
2. **キャリブレーション方式を「両方」にする。** クリック9点 + スムースパスートで、点数が 10 倍以上になります
3. **ドリフト補正を有効にする。** クリックした位置を見ていたと仮定して、使用中ずっと微修正が入ります
4. **姿勢を保つ。** 頭部姿勢の特徴量で補正してはいますが、キャリブレーション時と同じ距離・角度が一番強い
5. **眼鏡の反射を避ける。** 光源の位置を少しずらすだけで変わります
6. **720p 以上のカメラを使う。** 虹彩は画面上わずか十数ピクセルです

## 使い方

カメラ API は secure context 限定なので `file://` では動きません。ローカルサーバ経由で開いてください。

```bash
git clone <このリポジトリ>
cd webcam-eye-tracker
npm start                 # http://localhost:8080
```

1. **カメラを開始** — 初回は MediaPipe の wasm + モデル（約 13 MB）を CDN から取得します
2. **キャリブレーション** — 方式は「両方（推奨）」。約 45 秒
   - クリック 9 点: 点を**見つめたままクリック**
   - スムースパスート: 動く点を目で追う
3. **精度を測る** — キャリブレーションに使っていない 9 点で実測。ここで出た数字があなたの現実です
4. ずれてきたら **ドリフト補正** をオンにするか、キャリブレーションをやり直す

`Esc` でいつでも中止できます。

### オフライン / CDN なしで動かす

```bash
npm run setup          # MediaPipe 一式を ./vendor に取得し、ページを切り替える
npm run setup:revert   # CDN に戻す（--purge を付けると vendor/ も削除）
```

これで第三者へのリクエストがゼロになります。オフライン動作、厳しい CSP 下での運用、
CDN 障害への耐性が必要ならこちら。`vendor/` は `.gitignore` 済みなので、
`<meta name="eyetracker-assets">` が付いた状態の HTML はコミットしないでください
（clone 先で vendor/ が無く 404 になります。一応 CDN へフォールバックはします）。

## 配布する

### 1. GitHub Pages

`.github/workflows/pages.yml` が入っています。リポジトリの Settings → Pages で
Source を **GitHub Actions** にすれば、`main` への push で自動デプロイされます。
デプロイ前に `npm run setup` が走るので、公開されるサイトは CDN 非依存です。

### 2. 任意の静的ホスティング

ビルド不要の素の ES Modules なので、リポジトリをそのまま置けば動きます
（Netlify / Cloudflare Pages / S3 / nginx / どれでも）。**https 必須**です。

### 3. 他のページに組み込む

```js
import { EyeTracker } from './js/eyetracker.js';

const et = new EyeTracker();
await et.start();                       // カメラ + モデル読み込み
await et.calibrate({ mode: 'both' });   // キャリブレーション画面はライブラリ側が出す

et.on('gaze', ({ x, y, blink }) => { /* 毎フレーム */ });
et.on('fixation', ({ x, y, duration }) => { /* 注視が終わるたび */ });
```

ホスト側に専用のマークアップは要りません。キャリブレーション UI は Shadow DOM の中に
自前で組み立てるので、既存 CSS と衝突しません。動く例は [`examples/embed.html`](examples/embed.html)。

### 4. PWA としてインストール

`manifest.webmanifest` と `sw.js` が入っています。アプリシェルと MediaPipe 資産の
両方がキャッシュされるので、2 回目以降はオフラインでも起動します。

### プライバシー

映像・ランドマーク・視線データはすべてブラウザ内で処理され、どこにも送信されません
（ネットワークに出るのは MediaPipe の wasm とモデルの取得だけで、`npm run setup` すればそれも消えます）。
配布時の説明にそのまま使える性質です。ただし**カメラを使う以上、利用者への明示と同意は必要**です。

## API

### `new EyeTracker(options)`

| オプション | 既定 | 説明 |
|---|---|---|
| `video` | 自動生成 | 既存の `<video>` を使う（プレビュー表示したいとき） |
| `smoothing` | `0.55` | 0 = 追従優先 / 1 = 安定優先 |
| `driftCorrection` | `false` | クリック位置で継続的に自己補正 |
| `fixation` | `{}` | `velocityThreshold` (px/s), `minDurationMs`, `maxGapMs` |

### メソッド

| | |
|---|---|
| `await start()` / `stop()` / `destroy()` | カメラとモデルのライフサイクル |
| `await calibrate({ mode, cols, rows })` | `mode` は `'click' \| 'pursuit' \| 'both'`。中止時は `null` |
| `await validate({ points })` | 未学習の点で精度実測。`{ mean, p95, max, degrees }` |
| `on(event, fn) → unsubscribe` | `'gaze' \| 'fixation' \| 'face' \| 'status' \| 'error'` |
| `setSmoothing(0..1)` / `setDriftCorrection(bool)` | 実行中に変更可 |
| `loadModel()` / `clearModel()` | localStorage への永続化 |

### イベント

```js
// gaze: 毎フレーム
{ x, y, rawX, rawY, blink, fixation, timestamp }

// fixation: 注視が「終わった」ときに一度
{ x, y, start, end, duration, samples, dispersion }
```

## 仕組み

### 特徴量 — `js/features.js`

主信号は、虹彩中心が目頭・目尻の中点からどれだけズレているかを目の横幅で正規化した値です。
これだけだと頭が動いた瞬間に破綻するので、ランドマークから直接計算できる頭部姿勢の代理変数を足します。

| 特徴 | 中身 |
|---|---|
| 虹彩オフセット | 左右それぞれの `(nx, ny)`、その平均、2 次項 |
| ヨー | 鼻先から左右の目尻までの距離の差 |
| ピッチ | 目の線に対する鼻先の縦位置 |
| ロール | 左右の目尻を結ぶ線の角度 |
| スケール | 両目尻間距離（カメラ距離の逆数に相当） |
| 位置 | 両目の中点の画面内座標 |
| 交差項 | 虹彩オフセット × 頭部姿勢 |

計 24 次元。頭を動かすと虹彩オフセットと頭部姿勢は必ず相関するので、
その交絡を回帰側に解かせる、という設計です。

### 回帰 — `js/math.js`, `js/gaze.js`

z 標準化 → 切片を除いた L2 正則化リッジ回帰で `(x, y)` を直接予測。外部ライブラリなし
（Gauss-Jordan / 部分ピボット選択）。素の最小二乗と違うのは 3 点：

1. **λ は leave-one-target-out 交差検証で選ぶ。** 同一注視点のサンプルはほぼ同一なので、
   ランダム k-fold だとリークして λ が極端に小さく選ばれます。ホールドアウト単位は「注視点」です
2. **IRLS（Cauchy 重み）で再フィット。** キャリブレーション中の瞬き 1 回、
   虹彩の誤検出 1 回で地図全体が歪むのを防ぎます。外れ値 15% を混ぜたデータで
   素の最小二乗に勝つことをテストで固定しています
3. **オンライン追加は低い重みで入る。** ドリフト補正のクリックは、
   明示的なキャリブレーション点の 1/4 の重みしか持ちません

### スムースパスート — `js/calibration-ui.js`

動く点を追う方式は、同じ時間でクリック方式の 10 倍以上のサンプルが取れ、画面の被覆も連続的です。
ただし**眼は動く点に約 100 ms 遅れて追従する**ので、時刻 t のサンプルは
「今の点の位置」ではなく「t − 120 ms の点の位置」と対応付けます。この補正がないと系統誤差が乗ります。

### 注視点検出 — `js/fixation.js`

速度しきい値（I-VT）でサッケードと注視に分割します。多くの用途で欲しいのは毎フレームの座標ではなく
「ここを、この時間見ていた」という単位で、平滑化では消えないノイズもここで落ちます。

## テスト

```bash
npm test          # 29 件。線形代数・フィルタ・特徴量・注視点検出・学習/予測の通し
npm run setup     # 先に資産をローカル化（e2e はネットワーク不要になる）
npm start &
npm run test:e2e  # ヘッドレス Chromium で実アプリを起動して検証
```

`test/pipeline.test.js` は「虹彩位置が視線と頭部姿勢の既知の関数になっている合成顔」を作り、
9 点キャリブレーション → 未知の点で予測、という通しの流れが数値的に成立することを確認します。
ロバスト推定が素の最小二乗に勝つことも、ここで回帰テストとして固定しています。

`test/e2e/smoke.mjs` は Chromium の擬似カメラで**実アプリを起動**し、
ES モジュール解決・MediaPipe の読み込み・検出ループ・顔なし時の表示・
オーバーレイの生成と破棄・ブラウザ内での学習/予測を検証します。
合成映像には顔が無いので**精度の検証はできません**（そこは実機で「精度を測る」を使ってください）。

## 既知の限界

- 頭部の大きな移動で精度が落ちます。姿勢を変えたら測り直すのが確実です
- キャリブレーションはウィンドウサイズに紐づきます。リサイズしたら測り直してください
- 眼鏡の強い反射、低コントラストな照明では虹彩ランドマークが不安定になります
- 画面外への視線はクランプされます（画面内という前提のモデルです）
- モバイルでも動きますが、保持姿勢が安定しないぶん誤差は大きくなります
- 瞳孔径・輻輳・視深度は取れません（単眼 RGB の原理的な限界です）
